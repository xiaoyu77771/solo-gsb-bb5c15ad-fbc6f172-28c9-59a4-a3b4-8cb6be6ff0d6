# 舞台排练口令同步系统

面向舞台排练场景的口令（Cue）同步 Web 应用。导演编排演出序列，控制端逐条发出口令，仅目标岗位可确认；全部目标确认后才允许推进，超时与重复确认实时标记，断线重连自动恢复现场状态。进行中的口令可由**控制端撤回并纠正重发**：同一序号递增修订号、旧轮次封存为只读历史并重新开始完整确认时限，迟到的旧轮次确认与旧定时器回调一律拒绝。进行中的口令还可由**控制端暂停 / 恢复**：暂停时冻结剩余确认时长并撤销本轮计时器，各端显示暂停原因与剩余秒数，岗位确认、替岗、撤回与推进均被拒绝；恢复时沿用同一轮次按冻结余量重新计时，不累计误差。**多个控制端可同时在线，但同一时刻只有「指挥权租约」持有者可执行控制操作**：租约由服务端按心跳续期，断线或超时自动释放，过期租约可被其他控制端接管，竞争申请由服务端原子裁决。

技术栈：Node.js + Express + WebSocket（`ws`）+ 原生前端（无框架）。

## 快速开始（单条命令）

### 方式一：Docker Compose（推荐）

```bash
docker compose up --build
```

### 方式二：本地 Node.js（≥ 18）

```bash
npm install && npm start
```

启动后通过 **3000 端口** 访问各页面：

| 页面 | 地址 | 用途 |
| --- | --- | --- |
| 首页 / 日志 | <http://localhost:3000/> | 入口导航与本场事件日志 |
| 导演端 | <http://localhost:3000/director.html> | 创建演出序列（序号、口令、目标岗位、确认时限） |
| 控制端 | <http://localhost:3000/control.html> | 申请 / 释放指挥权租约，开始演出、监控确认状态、推进 / 暂停恢复 / 撤回纠正重发 / 重置 |
| 岗位端 | <http://localhost:3000/position.html> | 岗位上岗、接收口令、确认 |

> 修改端口：设置环境变量 `PORT`，如 `PORT=8080 npm start`，Compose 中同步调整 `ports` 映射。

## 指挥权租约（多控制端仲裁）

多个控制端可同时打开 <http://localhost:3000/control.html> 在线，但**同一时刻只有租约持有者**能执行：开始、推进、替岗、撤回、暂停、恢复、重置。非持有者的按钮在前端禁用，越权消息到达服务端同样被拒绝。

- **租约时长**：默认 **10 秒**（环境变量 `LEASE_TTL_MS` 可调，单位毫秒；Compose 中已显式配置为 `10000`）。持有期间控制端约每 3 秒（租约时长的 1/3）自动发送心跳续期。
- **申请**：任一控制端点击「✋ 申请指挥权」。租约空闲时立即授予；已被持有且未过期时，服务端拒绝并提示持有者与剩余时间（竞争申请由服务端原子裁决，同时申请只有一人成功）。
- **释放**：持有者点击「释放指挥权」主动交还，其他控制端即可申请。
- **接管流程**：持有者断线（连接关闭）或心跳超时（超过租约时长未续期）时，服务端**自动释放**租约并广播；此时任一控制端点击「申请 / 到期接管」即可获得指挥权。租约未过期时**不可抢占**。
- **状态展示**：状态快照实时展示持有者与剩余有效期（控制端顶部「指挥权租约」卡片每秒刷新倒计时）；授予、释放、申请被拒、迟到心跳均写入事件日志。
- **迟到心跳防护**：每次授予生成唯一租约凭证（token），心跳必须由持有连接携带当前凭证才能续期；旧连接 / 旧凭证的迟到心跳只被拒绝并记录（`stale-heartbeat-ignored`），**绝不续活新租约**。

## 使用流程

1. **导演端**：逐行填写口令内容与目标岗位（多个岗位用逗号分隔），设置确认时限（秒，3–600），点击「保存序列」。演出进行中序列锁定，需控制端重置后才能修改。
2. **控制端**：先在「指挥权租约」卡片点击「✋ 申请指挥权」获得租约（多控制端同时在线时，同一时刻仅一人持有，详见上文「指挥权租约」），然后点击「开始演出」发出第 1 条口令。页面实时展示每个目标岗位的状态：待确认 / 已确认 / 超时未确认 / 迟到确认，以及岗位在线情况。
3. **岗位端**：输入岗位名「上岗」（岗位名需与序列中的目标岗位完全一致，浏览器会记住）。本岗位是目标岗位时，「确认收到」按钮亮起。
4. **临时替岗**：当前口令尚有未确认目标时，控制端点击该目标旁的「⇄ 替岗」，从**在线且非本条有效目标**的岗位中选择替补并确认。接管后：原岗位立即失去本条确认权（页面划线标注「已由 ×× 接管」），替补岗位端出现「临时替岗」接管提示并可确认，其确认计入全员确认与推进条件；超时未确认标记也随确认权一并移交。替岗**仅对当前口令生效**，推进到下一条后仍使用导演编排的原目标。
5. **推进**：仅当当前口令的**全部有效目标**（含替补）都确认后，控制端才能推进到下一条；否则服务端拒绝并提示未确认岗位。
6. **撤回并纠正重发（修订）**：当前口令**仍在进行且尚未全员确认**时，控制端在「撤回并纠正重发」卡片中填写**撤回原因**（必填）与**修正版口令文本**（必填）后提交。服务端：
   - 将旧轮次的确认、超时未确认、临时替岗、起止/截止时间整体封存为**只读历史**（不可再修改）；
   - 在**同一序号**上把修订号 `revision` 从 1 递增（2、3…），替换口令文本并记录撤回原因；
   - 清空本轮全部状态，生成新的轮次凭证 `attemptId`，**重新开始完整确认时限**；
   - 迟到到达的旧轮次确认（携带旧 `attemptId` 或不带 `attemptId`）、旧超时定时器回调、旧替岗请求一律**拒绝并写入日志**（`stale-confirm-ignored` / `stale-timeout-ignored` / `stale-substitute-ignored`），绝不污染新轮次。

   岗位端确认时必须携带其最新状态快照中的 `attemptId`。控制端与岗位端实时展示**当前修订号、撤回原因及各旧轮次的只读结果**（已确认/迟到/超时/未确认及替岗关系），断线重连后经全量快照恢复，完全一致。**已推进或已完成（含全员确认完成）的口令不可撤回**；已完成的轮次同样封存为只读历史。
7. **暂停 / 恢复当前口令**：当前口令**仍在进行且尚未全员确认**时，控制端在「暂停 / 恢复当前口令」卡片中填写**暂停原因**（必填）后点击「暂停当前口令」。服务端：
   - **冻结剩余确认时长**（`remainingMs`，已超时则余量为 0）并**撤销本轮计时器**，暂停期间超过原时限也不会标记超时；
   - 各端实时显示**暂停原因与冻结的剩余秒数**（顶部横幅 + 倒计时区），岗位确认、临时替岗、撤回重发与推进**一律被拒绝**（暂停中的确认尝试写入日志 `paused-confirm-rejected`）；
   - 点击「恢复口令」后**沿用同一 `attemptId`**（不生成新轮次），按冻结余量重排截止时间重新计时，重复暂停 / 恢复**不累计误差**；旧定时器回调凭轮次凭证与定时器令牌双重校验，只能被拒绝并记录（`stale-timeout-ignored`），绝不写入超时状态。

   暂停与恢复均写入事件日志（`cue-paused` / `cue-resumed`），包含**操作者、原因与发生时间**；暂停状态随全量快照下发，**断线重连后各端恢复一致的暂停现场**。已全员确认的口令不可暂停；已超时但未全员确认的口令可暂停（余量冻结为 0）。
8. **重置**：控制端「重置场次」清空口令进度、全部修订档案与暂停状态（事件日志保留），导演端可重新编辑序列。

## 核心规则

- **指挥权租约**：多个控制端可同时在线，同一时刻仅租约持有者可执行开始 / 推进 / 替岗 / 撤回 / 暂停 / 恢复 / 重置（服务端逐条校验，越权消息一律拒绝；前端按钮同步禁用）。租约默认 10 秒，由持有者心跳续期；断线或心跳超时自动释放，过期租约可被任一控制端申请接管，未过期不可抢占。竞争申请由服务端原子裁决（单线程同步处理，检查与授予不可分割），同时申请只有一人成功。每次授予生成唯一凭证，心跳须由持有连接携带当前凭证；旧连接的迟到心跳只被拒绝并记录，绝不续活新租约。租约状态（持有者、剩余有效期）随全量快照下发，授予 / 释放 / 拒绝 / 迟到心跳均写入事件日志。
- **岗位隔离**：只有当前口令有效目标（原目标或接管后的替补）的岗位端能确认，其他岗位的确认请求被服务端拒绝。
- **临时替岗**：仅控制端可发起，且仅当目标尚未确认；替补必须在线且不是本条有效目标。服务端仅对当前口令原子更新有效目标与确认权限，下一条口令自动恢复导演编排的原目标。替岗的原岗位、替补岗位与发生时间写入事件日志，并随全量状态同步到各端，断线重连后保持一致。
- **状态不串场**：每条口令激活时确认表、超时表与替岗表整体重置，上一条的确认与替岗绝不带入下一条。
- **撤回并纠正重发（修订轮次）**：仅控制端可发起，且仅限当前进行中、尚未全员确认的口令（已推进/已完成的口令不可撤回，全员确认完成的口令也不可撤回）。每轮确认都有服务端生成的唯一 `attemptId`，岗位端确认消息必须携带其快照中的 `attemptId`；撤回后同序号 `revision` 递增、状态清空、完整确认时限重新计时，旧轮次的确认/超时/替岗/截止时间封存为只读历史（`cueHistory`，随全量快照下发，断线重连一致），旧确认、旧定时器回调与旧替岗请求只能被拒绝并记录（`stale-*-ignored`），绝不写入新轮次状态。
- **暂停 / 恢复**：仅控制端可发起，且仅限当前进行中、尚未全员确认的口令，暂停必须填写原因。暂停时服务端冻结剩余确认时长（`remainingMs`）并撤销本轮计时器；暂停期间岗位确认、替岗、撤回与推进均被服务端拒绝。恢复时沿用同一 `attemptId`，按冻结余量重排 `deadline` 重新计时，重复暂停 / 恢复不累计误差；每个定时器都携带轮次 `attemptId` 与单调递增的 `timerToken` 双重凭证，任何旧定时器回调只能被拒绝并记录，绝不写入超时状态。暂停状态（`paused` / `pauseReason` / `remainingMs` 等）随全量快照下发，断线重连后各端一致；暂停与恢复事件记录操作者、原因与发生时间。
- **超时标记**：到达确认时限仍未确认的岗位被实时标记为「超时未确认」并写入日志；超时后仍可确认，标记为「迟到确认」。
- **重复确认**：同一岗位对同一条口令的重复确认不改变状态，实时写入日志并标记。
- **断线重连**：岗位端断线后自动重连（1 秒间隔），重连后服务端下发全量状态快照，恢复当前口令、倒计时与本人确认状态；控制端可看到岗位在线 / 离线。
- **事件日志**：本场所有事件（发出口令、确认、迟到、重复、超时、替岗、上下线、推进、重置等）保存在内存并追加写入 `data/events-<场次ID>.jsonl`，各页面实时滚动展示。

## WebSocket 协议简述

连接地址：`ws://<host>:3000/ws`

- 客户端 → 服务端：
  - `hello`（登记角色/岗位/clientId/显示名）、`setSequence`
  - `lease-acquire`（控制端申请 / 接管指挥权租约；未过期被持有时拒绝）
  - `lease-release`（持有者主动释放租约）
  - `lease-heartbeat`（持有者心跳续期：**必须携带当前租约 `token`**，旧凭证/旧连接的迟到心跳一律拒绝）
  - `start`、`advance`、`reset`（**均需持有指挥权租约**）
  - `confirm`（岗位确认，**必须携带当前快照中的 `attemptId`**）
  - `substitute`（控制端临时替岗：`{ from, to, attemptId }`，需持有租约）
  - `recall`（控制端撤回并纠正重发：`{ reason, text }`，均为必填；仅限当前进行中且未全员确认的口令，需持有租约）
  - `pause`（控制端暂停当前口令：`{ reason }` 必填；仅限进行中且未全员确认时，需持有租约）
  - `resume`（控制端恢复当前口令：沿用同一 `attemptId` 按冻结余量重新计时，需持有租约）
- 服务端 → 客户端：
  - `state`（全量状态快照：含 `attemptId`、`revision`、`revisionReason`、只读 `cueHistory`、`substitutions` 与 `effectiveTargets`，暂停状态 `paused` / `pauseReason` / `pausedAt` / `pausedBy` / `remainingMs`，以及指挥权租约 `lease`（持有者、剩余有效期）与 `leaseTtlMs`，任何变化即广播，重连恢复依赖于此）
  - `lease-granted`（租约授予：仅发给持有者，含续期所需 `token` 与 `ttlMs`）
  - `error`（操作拒绝原因，如旧轮次确认被拒、不可撤回、口令已暂停、未持有指挥权租约等）
